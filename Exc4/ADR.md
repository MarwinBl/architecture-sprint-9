### <a name="_qmphm5d6rvi3"></a>**Решение**
[С4 диаграмма](С4.drawio)
Важно чтобы информация о ставках была единообразной как у нашей поддержки, так и у партнерского call-центра. Поэтому было принято решение передавать ставки в виде файлов. Это позволит избежать ошибок при передаче данных и упростит процесс обновления ставок.
Решение состоит из двух Use Cases. 
Первый - ручная отправка ставок сотрудником отдела кредитования по почте. Данный кейс ничего не стоит в реализации и поможет нам быстро запустить наш MVP. После реализации автоматизации - этот кейс будет альтернативой, повышающей отказоустойчивость банка.
Второй - автоматизированная отправка ставок с помощью сервиса управления депозитами. Данный кейс позволит нам избежать ошибок при ручной отправке и упростит процесс обновления ставок. В дальнейшем можно развивать передачу данных по АПИ. Кроме того данный сервис будет единым источником правды по ставкам для остальных сервисов банка.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Передать ссылку на наш сайт с актуальными ставками. Это можно использовать как дополнительное решение, когда не удалось доставить письмо по какой-либо причине.
Оба из Use Cases являются альтернативой друг другу и взаимозаменяемы. Служат для повышения надежности работы.


**Недостатки, ограничения, риски**

Есть риск того, что кредитный менеджер забудет добавить в получателей сотрудников партнерского call-центра. Для этого нужно, чтобы их руководитель самостоятельно проявлял заинтересованность, если он не получит ставки и обеспечить его общим номером отдела кредитования.
Есть риск того, что штат сотрудников поменяется или один из них сменит должность, но продолжит получать письма. Для этого необходимо попросить их руководителя создать ящик-алиас для его отдела, чтобы все письма приходили на него и пересылались сотрудникам отдела.
Есть риск недоступности сервиса управления депозитами. В этом случае переходим на вариант с ручной отправкой почтой.
